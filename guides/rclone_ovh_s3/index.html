    Transfer data to an OVH S3 bucket with rclone¶

    This guide shows how to copy data from a Linux server, a Mac or a Windows PC to an OVHcloud Object Storage bucket (S3) with rclone, and how to check that everything arrived intact. You always start with an exercise: you transfer dummy data, generated for the occasion, with exactly the same commands as for your real data. On a Mac or a PC, you can also try a graphical client, Cyberduck, on the same data.

    Moving the data to cold archive afterwards is optional and covered separately at the end of the page (Part 2).

    What you need¶

    Four things, whatever your system:

    • An OVHcloud account with a Public Cloud project. The storage is created and billed in this project.
    • A bucket in the project's Object Storage, with the S3 API. You need its name and its region (for instance eu-west-par, Paris).
    • Keys for this bucket: an access key and a secret key. They belong to an Object Storage user who has the right to read and write in the bucket.
    • A machine to work from: the Linux server, the Mac or the Windows PC that holds the data. The exercise of step 4 runs on this machine, with dummy data, before any real transfer.

    In most cases, the account, the bucket and the keys are provided by whoever administers the OVHcloud account for your team: you only receive the bucket name, its region and the two keys. If you have your own OVHcloud account, OVHcloud's documentation explains how to create a Public Cloud project, create a bucket and create an Object Storage user with its keys.

    Your values¶

    First choose where you will type the commands, then fill in the fields: every command on this page updates as you type, and you only have to copy it. Fields highlighted in yellow still hold an example value. Your values are kept in this browser for your next visit; nothing is sent anywhere.

    The exercise data and the logs always go to your home folder, in the folders rclone-exercise and rclone-logs: they need no field.

    Never type your access keys here

    Keys are typed only in the terminal, at step 2 (and in Cyberduck's own login window if you try it).

    Example: your values in the command that lists the content of the bucket. It changes nothing, and works once steps 1 and 2 are done.

    rclone lsf {{remote}}:{{bucket}}

    Choose Linux server, Mac or Windows above: the steps below then show the commands for your system only.

    Before you start¶

    • The bucket name (my-bucket), its region, the access key and the secret key (What you need).
    • An account on the Linux server that holds the data, with Internet access, and at least 2 GB of free space in your home directory for the exercise.The Terminal app (Applications, then Utilities) and at least 2 GB of free space in your home folder for the exercise.Windows PowerShell (Start menu, type PowerShell) and at least 2 GB of free space in your home folder for the exercise. Keep the computer plugged in and awake during transfers.
    • Administrator rights on your machine to install rclone (sudo on Linux and Mac). On a shared server where you do not have them, use the variant without administrator rights given at step 1.

    Part 1 — Transfer the data¶

    Step 1 — Install rclone¶

    With rclone's official installation script, which asks for your password (sudo) and installs the latest version:

    sudo -v ; curl https://rclone.org/install.sh | sudo bash
rclone version

    The last command must print a version number.

    Without administrator rights (shared server)

    This installs rclone in your own ~/bin folder; it works on a standard x86-64 server (uname -m prints x86_64).

    mkdir -p ~/bin && cd /tmp
curl -O https://downloads.rclone.org/rclone-current-linux-amd64.zip
unzip -o rclone-current-linux-amd64.zip
cp rclone-*-linux-amd64/rclone ~/bin/
cd -
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc
hash -r && which rclone && rclone version

    The output must show a path in your home directory ending in /bin/rclone, then a version number.

    With winget, which is part of recent Windows versions:

    winget install Rclone.Rclone

    Then close PowerShell, open a new PowerShell window, and check:

    rclone version

    Step 2 — Configure access to the bucket¶

    Paste this block. It asks for the access key, then for the secret key, which is not displayed while you type. If a configuration with the same name already exists, the block stops without changing anything: choose another name in "Your values" and copy the block again. Other rclone configurations are left untouched.

    if rclone listremotes | grep -qx "{{remote}}:"; then
  echo "A configuration named {{remote}} already exists: choose another name in Your values."
  rclone listremotes
else
  printf "Paste the access key, then Enter: "; read -r AK
  printf "Paste the secret key (nothing is displayed, this is normal), then Enter: "
  stty -echo; read -r SK; stty echo; echo
  rclone config create {{remote}} s3 provider=Other env_auth=false \
    access_key_id="$AK" secret_access_key="$SK" \
    region={{region}} endpoint=https://{{endpointhost}} \
    acl=private no_check_bucket=true > /dev/null
  unset AK SK
  chmod 600 "$(rclone config file | tail -1)"
  rclone listremotes
fi

    & {
  if ((rclone listremotes) -contains "{{remote}}:") {
    Write-Host "A configuration named {{remote}} already exists: choose another name in Your values."
  } else {
    $AK = Read-Host "Paste the access key, then Enter"
    $SS = Read-Host "Paste the secret key (nothing is displayed, this is normal), then Enter" -AsSecureString
    $SK = [Runtime.InteropServices.Marshal]::PtrToStringBSTR([Runtime.InteropServices.Marshal]::SecureStringToBSTR($SS))
    rclone config create {{remote}} s3 provider=Other env_auth=false access_key_id=$AK secret_access_key=$SK region={{region}} endpoint=https://{{endpointhost}} acl=private no_check_bucket=true | Out-Null
  }
  rclone listremotes
}

    The last command must print ovh: (and your other rclone configurations, if any). The secret key is now stored in rclone's configuration file, readable by you only: do not copy it anywhere else.

    Step 3 — Check access¶

    echo "test" | rclone rcat {{remote}}:{{bucket}}/access_test.txt
rclone lsf {{remote}}:{{bucket}}
rclone deletefile {{remote}}:{{bucket}}/access_test.txt

    The second command must print access_test.txt. If a command prints AccessDenied, check the keys (step 2), then contact whoever gave them to you.

    Step 4 — Practise with dummy data (mandatory)¶

    This step is not optional. It checks that your machine, the network and the bucket work together, without any risk for your real data.

    a) Create the generation script. Paste this block: it creates the file generate_test_data.sh in the current folder and makes it executable.

    Show the block that creates the script (60 lines) 
    cat > generate_test_data.sh <<'EOF'
#!/usr/bin/env bash
# Generates a tree of dummy data (random, incompressible) that mimics
# raw sequencing data, to test an rclone transfer. Runs on Linux and macOS.
# Usage: ./generate_test_data.sh TARGET_DIR [VOLUME_IN_GB]
#   VOLUME_IN_GB < 10  -> "quick test" set (~1 GB)
#   VOLUME_IN_GB >= 10 -> ~VOLUME_IN_GB GB (70 % as 1 GiB files, 30 % as 10 GiB files)
set -euo pipefail

DEST="${1:?Usage: $0 TARGET_DIR [VOLUME_IN_GB]}"
VOL="${2:-1}"
MIB=1048576

if [ -e "$DEST" ] && [ -n "$(ls -A "$DEST" 2>/dev/null)" ]; then
  echo "Error: $DEST exists and is not empty." >&2
  exit 1
fi

# Check free space before starting (requested volume + 10 %)
mkdir -p "$DEST"
NEEDED_GB=$(( (VOL < 10 ? 2 : VOL) * 11 / 10 ))
FREE_GB=$(( $(df -Pk "$DEST" | awk 'NR==2 {print $4}') / 1024 / 1024 ))
if [ "$FREE_GB" -lt "$NEEDED_GB" ]; then
  echo "Error: $NEEDED_GB GB of free space needed, only $FREE_GB GB available on this disk." >&2
  rmdir "$DEST" 2>/dev/null
  exit 1
fi

if [ "$VOL" -lt 10 ]; then
  N_MEDIUM=3;  S_MEDIUM=$(( 100 * MIB ))   # 3 x 100 MiB
  N_LARGE=1;   S_LARGE=$(( 600 * MIB ))    # 1 x 600 MiB: uploaded in several parts
else
  N_MEDIUM=$(( VOL * 70 / 100 )); S_MEDIUM=$(( 1024 * MIB ))
  N_LARGE=$(( VOL * 30 / 1000 )); S_LARGE=$(( 10240 * MIB ))
fi

mkdir -p "$DEST/run_01/small" "$DEST/run_01/medium" "$DEST/run_02/large" \
         "$DEST/folder with spaces/données accentuées"

# 2000 small files of 100 KiB (many objects, little volume)
for i in $(seq -w 1 2000); do
  head -c 102400 /dev/urandom > "$DEST/run_01/small/read_$i.bin"
done

for i in $(seq -w 1 "$N_MEDIUM"); do
  head -c "$S_MEDIUM" /dev/urandom > "$DEST/run_01/medium/sample_$i.fastq.gz"
done

for i in $(seq -w 1 "$N_LARGE"); do
  head -c "$S_LARGE" /dev/urandom > "$DEST/run_02/large/alignment_$i.bam"
done

# Tricky names: spaces, accents, parentheses
echo "witness file" > "$DEST/folder with spaces/données accentuées/échantillon (copie) n°1.txt"

echo "Done:"
du -sh "$DEST"
find "$DEST" -type f | wc -l | xargs echo "files:"

EOF
chmod +x generate_test_data.sh

    You can also download the script and read it first.

    b) Generate the data. They go to $HOME/rclone-exercise. The script refuses to start if the folder is not empty or if there is not enough space.

    mkdir -p "{{logs}}"
./generate_test_data.sh "{{exo}}" 1

    a) Nothing to create on Windows: generation is a single block, pasted at step b).

    b) Generate the data. They go to rclone-exercise. The block refuses to start if the folder is not empty or if there is not enough space.

    Show the generation block (33 lines) 
    & {
  $Dest = "{{exo}}"; $Vol = 1
  New-Item -ItemType Directory -Force -Path "{{logs}}" | Out-Null
  if ((Test-Path -LiteralPath $Dest) -and (Get-ChildItem -LiteralPath $Dest -Force | Select-Object -First 1)) {
    Write-Host "Error: $Dest exists and is not empty."; return
  }
  New-Item -ItemType Directory -Force -Path $Dest | Out-Null
  $Base = if ($Vol -lt 10) { 2 } else { $Vol }
  $Need = [math]::Floor($Base * 11 / 10)
  $Free = [math]::Floor((Get-Item -LiteralPath $Dest).PSDrive.Free / 1GB)
  if ($Free -lt $Need) {
    Write-Host "Error: $Need GB of free space needed, only $Free GB available on this disk."
    Remove-Item -LiteralPath $Dest; return
  }
  if ($Vol -lt 10) { $NM = 3; $SM = 100MB; $NL = 1; $SL = 600MB }
  else { $NM = [math]::Floor($Vol * 70 / 100); $SM = 1GB; $NL = [math]::Floor($Vol * 30 / 1000); $SL = 10GB }
  $rng = [Security.Cryptography.RandomNumberGenerator]::Create()
  function Write-Random([string]$Path, [long]$Bytes) {
    $buf = New-Object byte[] ([math]::Min($Bytes, 1MB))
    $fs = [IO.File]::Create($Path)
    try { $left = $Bytes; while ($left -gt 0) { $n = [int][math]::Min($left, $buf.Length); $rng.GetBytes($buf); $fs.Write($buf, 0, $n); $left -= $n } }
    finally { $fs.Dispose() }
  }
  foreach ($d in "run_01/small", "run_01/medium", "run_02/large", "folder with spaces/données accentuées") {
    New-Item -ItemType Directory -Force -Path (Join-Path $Dest $d) | Out-Null
  }
  for ($i = 1; $i -le 2000; $i++) { Write-Random (Join-Path $Dest ("run_01/small/read_{0:D4}.bin" -f $i)) 100KB }
  for ($i = 1; $i -le $NM; $i++) { Write-Random (Join-Path $Dest ("run_01/medium/sample_{0:D3}.fastq.gz" -f $i)) $SM }
  for ($i = 1; $i -le $NL; $i++) { Write-Random (Join-Path $Dest ("run_02/large/alignment_{0:D3}.bam" -f $i)) $SL }
  Set-Content -LiteralPath (Join-Path $Dest "folder with spaces/données accentuées/échantillon (copie) n°1.txt") -Value "witness file"
  $f = Get-ChildItem -LiteralPath $Dest -Recurse -File
  "Done: {0:N2} GB in {1} files" -f (($f | Measure-Object Length -Sum).Sum / 1GB), $f.Count
}

    1 GB: about 2000 small files, three medium ones and one large one, plus a file with spaces and accents in its name.

    c) Upload the data. First open a screen session, which keeps running even if you log out:

    screen -S transfer

    Then, inside this session:

    BW="{{bw}}"
rclone copy "{{exo}}" {{remote}}:{{bucket}}/EXERCISE \
  --fast-list --transfers 4 \
  --bwlimit "$BW" -P \
  --log-file "{{logs}}/exercise_copy.log" --log-level INFO || tail -n 5 "{{logs}}/exercise_copy.log"

    To leave screen without stopping the transfer: Ctrl+A then D. To come back: screen -r transfer.

    c) Upload the data. caffeinate -i keeps the Mac awake while rclone runs; keep the lid open.

    BW="{{bw}}"
caffeinate -i rclone copy "{{exo}}" {{remote}}:{{bucket}}/EXERCISE \
  --exclude .DS_Store --fast-list --transfers 4 \
  --bwlimit "$BW" -P \
  --log-file "{{logs}}/exercise_copy.log" --log-level INFO || tail -n 5 "{{logs}}/exercise_copy.log"

    c) Upload the data. Keep the PowerShell window open until the end.

    $BW = "{{bw}}"
rclone copy "{{exo}}" "{{remote}}:{{bucket}}/EXERCISE" --fast-list --transfers 4 --bwlimit $BW -P --log-file "{{logs}}\exercise_copy.log" --log-level INFO
if ($LASTEXITCODE -ne 0) { Get-Content "{{logs}}\exercise_copy.log" -Tail 5 }
    • Progress is displayed live (option -P); the detailed log is $HOME/rclone-logs/exercise_copy.log.
    • If rclone fails, the end of the command prints the last lines of this log, which say why (see Troubleshooting).
    • The BW line limits the bandwidth to 50MiB/s on weekdays from 8 am to 8 pm, and to 80MiB/s at night and at weekends, so as not to saturate the site network. Times are those of the machine.

    d) Check the copy, once the transfer is over:

    rclone check "{{exo}}" {{remote}}:{{bucket}}/EXERCISE --one-way --fast-list \
  --combined "{{logs}}/exercise_check.txt"
rclone size "{{exo}}"
rclone size {{remote}}:{{bucket}}/EXERCISE

    rclone check "{{exo}}" {{remote}}:{{bucket}}/EXERCISE --one-way --fast-list \
  --exclude .DS_Store --combined "{{logs}}/exercise_check.txt"
rclone size "{{exo}}" --exclude .DS_Store
rclone size {{remote}}:{{bucket}}/EXERCISE --exclude .DS_Store

    rclone check "{{exo}}" "{{remote}}:{{bucket}}/EXERCISE" --one-way --fast-list --combined "{{logs}}\exercise_check.txt"
rclone size "{{exo}}"
rclone size "{{remote}}:{{bucket}}/EXERCISE"

    The exercise succeeded if the check ends with 0 differences found and if the last two commands print the same number of objects and the same total size. --exclude .DS_Store leaves out the small files that Finder creates in every folder you open: they are useless in the bucket.

    Going further: measure the throughput

    With 1 GB, the exercise checks that everything works, but says little about how long a large transfer will take. To find out, generate a bigger set: the last number of the generation command is the volume in GB ($Vol at the start of the generation block). As a reference, 100 GB took 6 minutes to generate and 35 minutes to upload from a lab server. On a server, put such a volume on a data disk, never in your home directory, which is often on the system disk: filling it up can freeze the server. Then adapt the path in the copy, check and clean-up commands. The speed is displayed live by -P; for the average, divide the volume transferred by the elapsed time, both given in the last lines of the log.

    e) Optional: the same upload with Cyberduck. Cyberduck is a free graphical client for Mac and Windows. This tests it on the same data, then checks with rclone that what it sent is intact.

    1. Install Cyberduck from cyberduck.io/download.
    2. Click "Open Connection" and choose the protocol S3 (HTTPS) in the list at the top (if it is not there, enable it in the preferences, under Profiles). Server: s3.eu-west-par.io.cloud.ovh.net, port 443, then the Access Key ID and the Secret Access Key, typed in this window only.
    3. Open the bucket, create a folder named CYBERDUCK-EXERCISE (Action menu, then New Folder) and open it. Select everything inside the folder rclone-exercise of your home folder, in your file manager, and drag it into the Cyberduck window. Note how long the transfer takes.
    4. Check with rclone. The --download option makes rclone compare the content byte by byte: for large files, which Cyberduck sends in several parts, the bucket keeps no checksum that rclone can compare.
    rclone check "{{exo}}" {{remote}}:{{bucket}}/CYBERDUCK-EXERCISE --one-way --download \
  --exclude .DS_Store --combined "{{logs}}/cyberduck_check.txt"
rclone size "{{exo}}" --exclude .DS_Store
rclone size {{remote}}:{{bucket}}/CYBERDUCK-EXERCISE --exclude .DS_Store

    rclone check "{{exo}}" "{{remote}}:{{bucket}}/CYBERDUCK-EXERCISE" --one-way --download --combined "{{logs}}\cyberduck_check.txt"
rclone size "{{exo}}"
rclone size "{{remote}}:{{bucket}}/CYBERDUCK-EXERCISE"

    The check must end with 0 differences found, and the last two commands must print the same number of objects and the same total size. Keep the folder CYBERDUCK-EXERCISE for now: step 5 uses it.

    Step 5 — Practise managing files in the bucket (recommended)¶

    Day-to-day work is rarely one big transfer: a new file arrives, a batch of files must be stored, a file was put in the wrong place, another one must go. This step practises these operations on the exercise data, which are still in the bucket under EXERCISE.

    In a bucket, a folder is only a part of the files' paths. You never need to create a folder before copying a file into it, and a folder disappears by itself when its last file is moved or deleted.

    a) Prepare the new files: a 5 MB file, new_sample.bam, and a folder of ten 1 MB files, new_batch, both in your home folder.

    head -c 5242880 /dev/urandom > "{{newfile}}"
mkdir -p "{{newbatch}}"
for i in $(seq -w 1 10); do head -c 1048576 /dev/urandom > "{{newbatch}}/file_$i.bin"; done
ls -l "{{newfile}}" "{{newbatch}}"

    & {
  $rng = [Security.Cryptography.RandomNumberGenerator]::Create()
  function Write-Random([string]$Path, [int]$Bytes) { $b = New-Object byte[] $Bytes; $rng.GetBytes($b); [IO.File]::WriteAllBytes($Path, $b) }
  Write-Random "{{newfile}}" 5MB
  New-Item -ItemType Directory -Force -Path "{{newbatch}}" | Out-Null
  for ($i = 1; $i -le 10; $i++) { Write-Random (Join-Path "{{newbatch}}" ("file_{0:D2}.bin" -f $i)) 1MB }
  Get-ChildItem -LiteralPath "{{newfile}}", "{{newbatch}}" | Select-Object Name, Length
}

    b) Upload a new file, first into an existing folder:

    rclone copy "{{newfile}}" {{remote}}:{{bucket}}/EXERCISE/run_02/large
rclone lsf {{remote}}:{{bucket}}/EXERCISE/run_02/large

    rclone copy takes a destination folder. The lsf must list new_sample.bam next to the alignment_…bam files already there.

    Then into a folder that does not exist yet:

    rclone copyto "{{newfile}}" {{remote}}:{{bucket}}/EXERCISE/run_03/new_sample.bam
rclone lsf {{remote}}:{{bucket}}/EXERCISE/run_03

    rclone copyto takes the full name of the file at destination, which also lets you rename it on the way. The lsf must print new_sample.bam: the folder run_03 did not exist, the copy created it.

    c) Upload a new folder, then check it:

    rclone copy "{{newbatch}}" {{remote}}:{{bucket}}/EXERCISE/new_batch
rclone check "{{newbatch}}" {{remote}}:{{bucket}}/EXERCISE/new_batch --one-way

    Name the folder in the destination

    rclone copy copies the content of a folder. Without /new_batch at the end of the destination, the ten files would land loose in EXERCISE, mixed with the rest.

    d) Move and rename. The files are moved inside the bucket, without being uploaded again:

    rclone moveto {{remote}}:{{bucket}}/EXERCISE/run_03/new_sample.bam {{remote}}:{{bucket}}/EXERCISE/run_01/sample_renamed.bam
rclone move {{remote}}:{{bucket}}/EXERCISE/new_batch {{remote}}:{{bucket}}/EXERCISE/run_02/new_batch
rclone lsf {{remote}}:{{bucket}}/EXERCISE
rclone lsf {{remote}}:{{bucket}}/EXERCISE/run_02

    moveto moves one file and can rename it; move moves the content of a folder, with the same rule as copy: name the folder in the destination. The first lsf no longer lists run_03/ nor new_batch/: once empty, they are gone. The second lists new_batch/ in its new place.

    e) Delete. Always run the command with --dry-run first: it deletes nothing and only shows what would be deleted.

    rclone deletefile {{remote}}:{{bucket}}/EXERCISE/run_01/sample_renamed.bam --dry-run

    The output must name sample_renamed.bam only, followed by Skipped delete as --dry-run is set. Then, and only then, delete it for real:

    rclone deletefile {{remote}}:{{bucket}}/EXERCISE/run_01/sample_renamed.bam

    deletefile deletes exactly one file and refuses a folder: it is the safest way to delete. To delete a whole folder, use rclone purge:

    rclone purge permanently deletes everything under the given path, without confirmation and without a trash

    A mistake in the path can wipe out the whole bucket, with all the data it holds. Read the path three times before pressing Enter, and run the command with --dry-run first.

    rclone purge {{remote}}:{{bucket}}/EXERCISE/run_02/new_batch --dry-run

    The output must end with EXERCISE/run_02/new_batch: Skipped purge directory as --dry-run is set: check that this path is the folder to delete, and nothing above it. Then delete it for real, and check that only large/ remains in run_02:

    rclone purge {{remote}}:{{bucket}}/EXERCISE/run_02/new_batch
rclone lsf {{remote}}:{{bucket}}/EXERCISE/run_02

    f) Optional: the same operations with Cyberduck, in the folder CYBERDUCK-EXERCISE:

    1. Drag new_sample.bam from your home folder into run_01.
    2. Rename it: select it, press Return, type renamed.bam, press Return again.
    3. Move it: Edit menu, Cut; open run_02; Edit menu, Paste ("Édition", "Couper", "Coller" if Cyberduck is in French).
    4. Drag the folder new_batch from your home folder into CYBERDUCK-EXERCISE.

    5. Look at the result with rclone:

      rclone lsf {{remote}}:{{bucket}}/CYBERDUCK-EXERCISE/run_01
rclone lsf {{remote}}:{{bucket}}/CYBERDUCK-EXERCISE/run_02
rclone lsf {{remote}}:{{bucket}}/CYBERDUCK-EXERCISE/new_batch

      run_02 must list renamed.bam next to large/, and new_batch its ten files. With an OVHcloud bucket, Cyberduck on Mac can stop with a connection error during a rename or a move, and leave the original file in place: if run_01 still lists new_sample.bam or renamed.bam, delete them in Cyberduck. rclone does not have this problem (step d).

    6. Delete renamed.bam: select it, then Delete ("Effacer" in French), and confirm.

    g) Clean up the bucket (both exercise folders) and your computer. Same care as above: the path must end with /EXERCISE.

    rclone purge {{remote}}:{{bucket}}/EXERCISE

    In Cyberduck, select the folder CYBERDUCK-EXERCISE at the root of the bucket, choose Delete ("Effacer" in French) and confirm: Cyberduck removes the folder and everything in it. Do it in Cyberduck rather than with rclone purge, which would leave the empty folder created by Cyberduck behind.

    rm -rf "{{exo}}" "{{newfile}}" "{{newbatch}}"

    Remove-Item -LiteralPath "{{exo}}", "{{newfile}}", "{{newbatch}}" -Recurse -Force

    Then send the files of the $HOME/rclone-logs directory to whoever supports you.

    Step 6 — Transfer the real data¶

    The same commands, with the directory of the real data (/path/to/data) and the destination directory in the bucket (my-dataset). First look for symbolic links, which rclone ignores by default: if the following command prints anything, ask for advice before going further.

    find "{{src}}" -type l | head

    Get-ChildItem -LiteralPath "{{src}}" -Recurse -Attributes ReparsePoint | Select-Object -First 10 -ExpandProperty FullName

    Open a screen session, then start the transfer inside it:

    screen -S transfer

    BW="{{bw}}"
rclone copy "{{src}}" "{{remote}}:{{bucket}}/{{dst}}" \
  --fast-list --transfers 4 \
  --bwlimit "$BW" -P \
  --log-file "{{logs}}/transfer_copy.log" --log-level INFO || tail -n 5 "{{logs}}/transfer_copy.log"

    BW="{{bw}}"
caffeinate -i rclone copy "{{src}}" "{{remote}}:{{bucket}}/{{dst}}" \
  --exclude .DS_Store --fast-list --transfers 4 \
  --bwlimit "$BW" -P \
  --log-file "{{logs}}/transfer_copy.log" --log-level INFO || tail -n 5 "{{logs}}/transfer_copy.log"

    $BW = "{{bw}}"
rclone copy "{{src}}" "{{remote}}:{{bucket}}/{{dst}}" --fast-list --transfers 4 --bwlimit $BW -P --log-file "{{logs}}\transfer_copy.log" --log-level INFO
if ($LASTEXITCODE -ne 0) { Get-Content "{{logs}}\transfer_copy.log" -Tail 5 }

    Once the transfer is over, check:

    rclone check "{{src}}" "{{remote}}:{{bucket}}/{{dst}}" --one-way --fast-list \
  --combined "{{logs}}/transfer_check.txt"

    Troubleshooting¶

    • The copy command returns at once, or ends with Errors: 1 or more: read the last lines of the log, which the command prints in that case. didn't find section in config file means that the rclone configuration name in "Your values" is not the one created at step 2 (the command rclone listremotes lists the existing ones). directory not found means that the source directory does not exist on this machine: check its path in "Your values".
    • AccessDenied: the keys were mistyped at step 2. Delete the configuration with rclone config delete ovh, then paste the step 2 block again.
    • rclone is not found after installation: open a new terminal window and try again.

    • The site network or the machine slows down: stop rclone (Ctrl+C), lower both bandwidths in "Your values", copy the command again and restart it. Once all transfers are over, this command deletes interrupted uploads older than 24 hours, which would otherwise still be billed in the bucket:

      rclone backend cleanup {{remote}}:{{bucket}}

    • The check finds differences: run the rclone copy command again with --checksum added, then check again.

    Part 2 — Cold archive (optional)¶

    This part only concerns data that have already been transferred and checked, and that you decide to keep for a long time without reading them. The decision belongs to the people responsible for the data.

    OVHcloud offers its cheapest storage class, Cold Archive, only in the Paris 3-AZ region (eu-west-par): the bucket must have been created there. Three constraints to know before deciding:

    • 180 days minimum: a file archived, then deleted or replaced before 180 days is billed until the end of that period.
    • Delayed reading: an archived file must be restored before it can be read; the restoration is billed and can take up to 48 hours.
    • File-by-file restoration: it is better to bundle small files into tar archives (for instance one per sequencing run) before the transfer.

    Two ways to do it:

    • Lifecycle rule (recommended): in the OVHcloud Control Panel, Lifecycle tab of the bucket, create a rule that transitions objects to Cold Archive after N days. Files move automatically; the transition itself is free.
    • Direct upload to the archive: add --s3-storage-class DEEP_ARCHIVE to the rclone copy command. Simpler, but leaves no room for mistakes.

    To restore an archived directory and keep it readable for 7 days: the restoration does not touch the archived version, which stays in Cold Archive. It is not a swap. It creates a temporary readable copy alongside, billed for its lifetime, which disappears by itself after the 7 days.

    rclone backend restore "{{remote}}:{{bucket}}/{{dst}}" -o priority=Standard -o lifetime=7

    See OVHcloud's Cold Archive FAQ for current conditions and prices.

    Appendix — The generation script (Linux and Mac)¶

    The same script as in step 4 a), without the command that creates the file.

    Show the script 
    #!/usr/bin/env bash
# Generates a tree of dummy data (random, incompressible) that mimics
# raw sequencing data, to test an rclone transfer. Runs on Linux and macOS.
# Usage: ./generate_test_data.sh TARGET_DIR [VOLUME_IN_GB]
#   VOLUME_IN_GB < 10  -> "quick test" set (~1 GB)
#   VOLUME_IN_GB >= 10 -> ~VOLUME_IN_GB GB (70 % as 1 GiB files, 30 % as 10 GiB files)
set -euo pipefail

DEST="${1:?Usage: $0 TARGET_DIR [VOLUME_IN_GB]}"
VOL="${2:-1}"
MIB=1048576

if [ -e "$DEST" ] && [ -n "$(ls -A "$DEST" 2>/dev/null)" ]; then
  echo "Error: $DEST exists and is not empty." >&2
  exit 1
fi

# Check free space before starting (requested volume + 10 %)
mkdir -p "$DEST"
NEEDED_GB=$(( (VOL < 10 ? 2 : VOL) * 11 / 10 ))
FREE_GB=$(( $(df -Pk "$DEST" | awk 'NR==2 {print $4}') / 1024 / 1024 ))
if [ "$FREE_GB" -lt "$NEEDED_GB" ]; then
  echo "Error: $NEEDED_GB GB of free space needed, only $FREE_GB GB available on this disk." >&2
  rmdir "$DEST" 2>/dev/null
  exit 1
fi

if [ "$VOL" -lt 10 ]; then
  N_MEDIUM=3;  S_MEDIUM=$(( 100 * MIB ))   # 3 x 100 MiB
  N_LARGE=1;   S_LARGE=$(( 600 * MIB ))    # 1 x 600 MiB: uploaded in several parts
else
  N_MEDIUM=$(( VOL * 70 / 100 )); S_MEDIUM=$(( 1024 * MIB ))
  N_LARGE=$(( VOL * 30 / 1000 )); S_LARGE=$(( 10240 * MIB ))
fi

mkdir -p "$DEST/run_01/small" "$DEST/run_01/medium" "$DEST/run_02/large" \
         "$DEST/folder with spaces/données accentuées"

# 2000 small files of 100 KiB (many objects, little volume)
for i in $(seq -w 1 2000); do
  head -c 102400 /dev/urandom > "$DEST/run_01/small/read_$i.bin"
done

for i in $(seq -w 1 "$N_MEDIUM"); do
  head -c "$S_MEDIUM" /dev/urandom > "$DEST/run_01/medium/sample_$i.fastq.gz"
done

for i in $(seq -w 1 "$N_LARGE"); do
  head -c "$S_LARGE" /dev/urandom > "$DEST/run_02/large/alignment_$i.bam"
done

# Tricky names: spaces, accents, parentheses
echo "witness file" > "$DEST/folder with spaces/données accentuées/échantillon (copie) n°1.txt"

echo "Done:"
du -sh "$DEST"
find "$DEST" -type f | wc -l | xargs echo "files:"
